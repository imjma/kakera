# Telegram sharing makes persistence and repeat intent explicit

Kakera distinguishes explicit Telegram intents rather than inferring them from lookup failure: `share/telegram` requests save a Capture before idempotent delivery, `kakera telegram SELECTOR` publishes a configured-folder Obsidian Note with resend confirmation, `--telegram-only URL` makes a Transient Telegram Delivery, and `kakera telegram-only SELECTOR` publishes a note without mutating it. Durable acknowledgements live under `kakera.shared.telegram`, keyed by numeric chat, while both receipt-free forms intentionally send on every invocation and cannot resolve an uncertain API outcome. No note command falls back to fetching a missing URL because that would turn a failed lookup into an unrequested download, local write, or external post.
