# Telegram sharing makes persistence and repeat intent explicit

Kakera distinguishes explicit Telegram intents rather than inferring them from lookup failure: `share/telegram` requests save a Capture before idempotent delivery, `kakera share telegram SELECTOR` publishes a configured-folder Obsidian Note with resend confirmation, `--share telegram-only URL` makes a Transient Telegram Delivery, Inbox/Todoist `share/telegram-only` is the same transient request from a queue item, `kakera telegram` is Telegram Intake of that transient request from an allowed user's private message, and `kakera share telegram-only SELECTOR` publishes a note without mutating it. Durable acknowledgements live under `kakera.shared.telegram`, keyed by numeric chat, while receipt-free forms intentionally send on every invocation and cannot resolve an uncertain API outcome. A queue group with `share/telegram-only` completes only when every URL delivers, because there is no Source Note to record a Failed Source. No note command falls back to fetching a missing URL because that would turn a failed lookup into an unrequested download, local write, or external post. Command spellings are recorded in ADR 0004.
